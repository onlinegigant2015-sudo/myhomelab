# Сводка
DHCP сервер в RouterOS настраивается через 3 сущности:
- IP Pool - диапазон IP адресов
- DHCP Network - параметры конкретной подсети (какой будет выдаваться gateway, dns-server, domain suffix и т.д.)
- DHCP Server - сам сервер, который включает в себя предыдущие компоненты

В подсети клиенты делают DORA-запрос, которые состоит из следующих шагов:
1) Discover - клиент направляет широковещательный запрос (broadcast), чтобы найти DHCP-сервер. (68 порт)
2) Offer - сервер получает broadcast запрос от клиента и возвращает ему запрос предложение, где содержится предложенный свободный IP адрес. (67 порт) 
3) Request - клиент получает offer запрос и подтверждает его. (68 порт)
4) Ack - сервер получает request запрос от клиента и подтверждает "сделку". (67 порт)

Догадка: если по какой-то причине клиенту (причин я не знаю) не устраивает предложенный offer от сервера, 3 шаг просто не происходит.

# Команды для настройки DHCP
```bash
/ip pool add name=X-pool ranges=X.X.X.Y-X.X.X.Z
/ip dhcp-server network add address=X.X.X.X/M gateway=X.X.X.1 dns-server=X.X.X.1
/ip dhcp-server add interface=... address-pool=X-pool
```
# Возможные проблемы
- Пинг до публичного DNS-сервера идет, но имя не разрешается. Причины:блокировка удаленных запросов в настройках dhcp-сервера и в firewall'е, который настроен на строгую фильтрацию трафика и блокирует порты, которые нужны для dns. Решение: прописать `ip dns set allow-remote-requests yes` и разрешить использовать порт 53 (DNS) по протоколам udp/tcp.
