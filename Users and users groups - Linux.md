# Users

**Пользователь**-объект в
Linux,которыйможетвзаимодействовать с системой.  
Он устроен следующим образом:

<div align=center><img width="347/3" height="281/3" alt="image" src="https://github.com/user-attachments/assets/7865c4df-7552-4faf-bf87-57c81a22d3a4" /></div>

1. **UID** - главный идентификатор пользователя. Это числовой уникальный идентификатор в пределах одной машины. UID - это идентификатор для системы, чтобы система могла взаимодействовать с пользователем и пользователь мог взаимодействовать с системой.
2. **Username** - это удобно читаемое для человека имя пользователя, чтобы можно было входить в пользователя, быстро находить его и взаимодействовать с ним (например добавлять, смотреть группы). Username != UID.
3. **GID** - Primary GID для пользователя. Идентификатор группы пользователя. В случае с Primary GID один пользователь может иметь только один Primary GID. О видах GID я расскажу более детально чуть позже.
4. **home** - путь до домашней папки пользователя. Например `/home/admin`.
5. **shell** - путь до интерактивной оболочки. Интерактивная оболочка, грубо говоря - это штука, которая позволяет человеку удобно взаимодействовать с системой через терминал.
6. **GECOS** - это прочая информация о пользователе. Номер телефона, адрес и т.д.

# Access

<div align=center><img width="262" height="267" alt="image" src="https://github.com/user-attachments/assets/34f577f6-df4e-4a96-b63f-9f06069be6e1" /></div>

Каждый объект в Linux имеет владельца (owner) и группу (group). Когда объект создается каким-либо пользователем, например `user1` с `UID = 1010`  и `GID = 1010`, объект получает владельца 1010 и группу 1010.Когда  `user2` с `UID = 1020`  и `GID = 1020` попытается как-то взаимодействовать с файлом, и если в `others` отсутствуют права на чтение, запись, выполнение, он получит ошибку `permission denied`, потому что он не прошел проверку прав доступа.  
Если ввести команду `ls -la` файлы будут выводится в следующем виде:

```bash
                                  
drwxr-x--- admin admin 4096 Oct 14 04:51 .             
                          
```

Где

d — тип объекта (директория).

rwx — права владельца (read, write, execute).

r-x — права группы (read, execute, без write).

--- — права остальных (нет прав).

admin admin — владелец и группа-владелец.

## `umask`
Команда задает маску прав доступа по умолчанию для новых файлов и директорий. 
Она не меняет права уже существующих объектов, а работает как фильтр при их создании.
- По умолчанию новой папке дается `777`, а файлу — `666`.
- Из этих прав вычитается значение `umask`. Например, при `umask 022` новая папка получит права `755` (777 - 022).
- Флаг `-S` (symbolic) показывает текущую маску в буквенном виде (например, `umask -S` выведет `u=rwx,g=rx,o=rx`).

# Groups

Группа - это механизм коллективного доступа. Вместо того, чтобы выдавать каждому пользователю какой-то конкретные права, достаточно необходимые права выдать на группу, а самого пользователя включить в эту группу.В Linux существует два вида GID:

1. Primary GID - уникальный идентификатор пользователя/пользователей. Нужен, чтобы при создании файлов файл получал записи о владельце и Primary GID владельца. Запись о Primary GID хранится в файле `/etc/passwd`
2. Supplementary GID - дополнительные группы для пользователя. Один пользователь может иметь множество дополнительных групп (до десятков тысяч), так же как группа может иметь множество пользователей. Запись о Supplementary GID хранится в файле `/etc/group`



| Тип пользователя | Тип группы | Отношение                                 |
|---------------------------------|---------------------|----------------------------------------------------|
| default users                   | Primary GID         | 1:1 (во многих дистрибутивах) |
| other users                     | Primary GID         | N:1                                                |
| all users                       | Supplementary GID   | M:N                                                |


# ACL (Access control list)

Если представить, что существует директория `/project` и существуют пользователи `tester` и `developer` нужно решить проблему с доступом.  
Во-первых нужно создать группу `project`, добавить туда пользователей `tester` и `developer`, а для остальных ограничить доступ к этой папке. Главная проблема решена штатными средствами Linux. Но появляется нюанс.

Оказывается, нужно для пользователя `developer` дать полный доступ к папке `/project` (`rwx`), а для пользователя `tester` дать доступ только к чтению и выполнению (`r-x`). Штатными средствами это сделать не получится. Только через костыли. Потому что если создать дополнительные группы `developers` и `testers` проблему это не решит, потому что для объекта Linux можно лишь только разрешать права для одной группы. 1 объект = 1 группа.

И для этих сложностей придумали инструмент `ACL`.

ACL - это не отдельный файл, это расширенный атрибут объекта (xattr - extension attribute). Он хранится в inode, рядом с обычными правами.

ACL состоит из записей ACE (Access control entries) - каждая запись хранит в себе: кто и что может делать с объектом.

Существуют расширенные записи ACL, которые позволяют решить проблему с доступом из примера с папкой `/project`. Это `user:<name>:<permissions>`,`group:<name>:<permissions>`.

Так же отдельной записью идет запись `mask:<permissions>`, которая ограничивает максимальные права для всех расширенных записей, а так же для группы владельца.

Маска выступает в роли второго операнда в логическом умножении `permissions & mask`.

## Алгоритм проверки доступа в linux

Когда процесс (с UID и списком GID) пытается открыть файл, ядро смотрит на ACL строго по порядку. При первом совпадении проверка останавливается:

1. Это владелец файла?  
  Применяются права из `user::`.
2. Есть ли запись для конкретного UID?  
  Применяются права из `user:<name>`, ограниченные маской.
3. Совпадает ли Primary GID с группой файла или есть запись для любой из его Supplementary GID?  
  Применяются права из `group::` или `group:<name>`, ограниченные маской. Если пользователь входит в несколько групп, и для одной из них есть ACE, он получит права. Если для нескольких - объединятся максимальные права.
4. Ничего не совпало?  
  Применяются права из `other::`.


# `/etc/sudoers`

Это файл, где хранится конфиг программы `sudo`.  
`sudo` - это как делегирование прав в Active Directory.  
Записи там представлены в следующем виде:`<Пользователь> <какой хост?> = (<от какого имени выполнять?>) <что выполнять?>`  
Редактировать этот файл можно только через `sudo visudo`!!!
